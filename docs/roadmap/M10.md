# M10 enterprise delivery hardening plan

Branch: `feature/m10-enterprise-hardening`

M10 is the accepted hardening module after the M9 release. It makes a clean
self-hosted installation operable over upgrades and gives operators explicit
controls for recovery, observability, traffic safety, and data lifecycle.

## Scope

- Installation and upgrades: versioned images, migration `000009`, startup
  ordering, health/version probes, and an operator runbook.
- Backup and restore: atomic custom-format PostgreSQL backups; restore is
  explicitly acknowledged and never runs implicitly during startup.
- Metrics and OpenTelemetry: Prometheus exposition with bounded route labels,
  build/version data, request status classes, and W3C traceparent/request-ID
  propagation at the HTTP boundary. `OTEL_EXPORTER_OTLP_ENDPOINT` remains a
  stable configuration boundary for a collector integration.
- Rate limiting: per-client fixed windows for API and webhook traffic with
  `429`, `Retry-After`, bounded client state, and health/metrics exemptions.
- Retention enforcement: transactional cleanup of old run events, audit events,
  webhook deliveries, and completed outbox records; pending operational work is
  retained. Cleanup is available as a CLI command and worker daily loop.
- Security baseline: secure transport headers, non-root server image, bounded
  request bodies, token-protected metrics when configured, secret-free backup
  runbook, and explicit restore confirmation.
- Load testing: bounded concurrent health-stack regression test and a repeatable
  Make target.

## Acceptance gate

```text
Frontend: lint, typecheck, test
Go: all tests, race detector, go vet
Database: migration up/down including 000009; isolated PostgreSQL retention cleanup
HTTP: metrics auth, stable labels, rate-limit response, security headers, trace correlation
Operations: shell syntax, backup safety checks, restore acknowledgement checks, compose config
Load: 512 requests / 32 workers through the hardened HTTP stack
Documentation: M10 acceptance evidence and operator runbook
```

M10 remote publication remains separately authorized. Local completion does not
authorize pushing, opening/merging a PR, or creating a release tag.
