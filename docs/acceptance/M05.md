# M05 acceptance record

Branch: `feature/m5-code-review`

Gate status: **OPEN — implementation and automated verification passed; real AC execution and GitHub publication passed, but private-repository checkout is blocked**

## MVP slice

- Added `REPOMENDER_FEATURE_M5_CODE_REVIEW`, gated on M2 SCM, M3 AC execution,
  and M4 task core.
- Extended the GitHub adapter to normalize `pull_request` actions with the
  repository, PR number, branches, immutable head SHA, author, and installation.
- Verified webhook deliveries are deduplicated before a review task is created.
- Created idempotent `code_review` tasks keyed by repository, PR number, and
  head SHA; newer commits supersede prior review tasks.
- Added strict v1 review-result validation (unknown fields, unsafe paths,
  invalid severities, line ranges, confidence, and finding count are rejected).
- Persisted findings and evidence through the task store and exposed them in
  task detail responses and the API-backed Code Reviews UI.
- Added the M5 worker processor: immutable commit execution through AC, ordered
  run events, structured result persistence, GitHub Check Run, and PR comment
  publication using short-lived installation tokens.
- Added explicit AC project and agent configuration (`REPOMENDER_AC_PROJECT_ID`
  and `REPOMENDER_AC_AGENT_NAME`) and a Responses-compatible strict schema whose
  required properties cover every nested Finding field.
- Supersession now matches the provider repository ID when an M2 repository
  snapshot is not present, which keeps webhook retries safe during initial sync.
- GitLab remains compiled but runtime-disabled.
