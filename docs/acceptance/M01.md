# M01 acceptance record

Date: 2026-07-30

## Delivered MVP

- OIDC Authorization Code flow with S256 PKCE, signed ID-token validation, and
  verified-email enforcement.
- One-time local administrator bootstrap protected by a PostgreSQL advisory lock.
- Server-side opaque sessions with database-enforced expiry.
- Session-bound CSRF tokens for state-changing requests.
- `Admin`, `Maintainer`, `Developer`, and `Auditor` domain roles.
- Admin-only user listing with HTTP 403 enforcement for non-admin roles.
- Login/bootstrap UI and local-login fallback when OIDC is unavailable.

## Real OIDC smoke test

Dex v2.44.0 ran as an actual local OpenID Provider using
`compose.oidc-smoke.yaml`. RepoMender discovered its metadata and completed the
browser-equivalent flow through Dex:

```text
RepoMender OIDC start
→ Dex authorization endpoint
→ local Dex authentication
→ authorization-code callback
→ PKCE verifier exchange
→ signed ID-token verification
→ RepoMender server session
```

- The authorization request contained `code_challenge_method=S256`.
- The callback returned to `http://localhost:18088/settings`.
- `/api/v1/auth/me` returned the persisted, verified-email OIDC identity with
  role `developer`.
- The developer session received HTTP 403 from the admin-only users endpoint.

The Dex credentials and client secret committed under `deploy/oidc-smoke/` are
test-only and must never be reused outside local acceptance.

Local M01 implementation, database integration, clean-stack, and real OIDC
acceptance requirements are satisfied. M01 still requires a green remote CI run
before it can be tagged and merged. M02 must not begin before that gate is
