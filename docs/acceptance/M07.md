## Implemented MVP slice

- Added `REPOMENDER_FEATURE_M7_APPROVALS`, gated on M4 task persistence and the
  accepted M6 dependency chain.
- Added the reusable `ApprovalRequest` state machine for `repair_plan`,
  `publish_patch`, and `sandbox_network` actions.
- Added pending, approved, rejected, expired, cancelled, and consumed states
  with risk, exact action digest, requester, eligible roles, decision actor,
  reason, expiry, consumption, cancellation, metadata, and immutable timestamps.
- Added decision and consumption idempotency keys; repeated valid requests do
  not repeat a decision or protected action.
- Added the exact-digest consumption gate. Changed plans, patches, or network
  policies cannot consume an earlier approval.
- Enforced Admin/Maintainer approval policy. Developer and Auditor decisions
  return 403 and create denial audit evidence.
- Added sandbox network metadata validation requiring an explicit non-wildcard
  destination list and network policy; the metadata is retained with the exact
  action digest.
- Added authenticated, CSRF-protected approval inbox/detail/decision/consume/
  cancel APIs and replaced the approval UI mock path with API-backed state.
- Added migration `000006_approvals` and a reusable `compose.m7-smoke.yaml`
  overlay without changing M4–M6 task routing.

## Security acceptance

- Missing CSRF returns 403 for approval mutations.
- Auditor requests are denied at the HTTP boundary; Auditor decision attempts
  reach the domain policy and persist a `denied` audit event.
- Developer decisions are denied by the domain policy even when a request is
  otherwise valid.
- Pending, expired, rejected, cancelled, and consumed requests cannot execute
  through the consumption gate.
- Action digest mismatch is rejected before state changes.
- Sandbox network approvals cannot contain wildcard or newline destinations and
  require an explicit policy string.
