## Delivered scope

- Added the M9 automation domain and PostgreSQL stores under
  `server/internal/automations/`.
- Added migration `000008_automations` with draft revisions, immutable
  published versions, trigger deduplication, and run history bound to the
  exact template version used.
- Added admin-only configuration API:
  list/create/read/update, publish, activate, disable, delete, version history,
  run history, and manual trigger endpoints under `/api/v1/automations`.
- Configuration mutations require the admin role, session CSRF token, and
  re-authentication with the local administrator credential via
  `X-Reauth-Password`.
- Added provider/event/repository-scope validation, approval-policy safety
  checks, optimistic revision conflicts, deterministic trigger keys, and
  transaction-scoped concurrency limits.
- Added the admin overview endpoint and Settings view for SCM/AC health,
  retention settings, Agent template inventory, budget use, and the automation
  audit lookup path.
- Integrated enabled templates with verified GitHub webhooks. Code review,
  CI diagnosis, and issue repair tasks continue through the existing M5/M6/M8
  worker and approval paths; issue repair templates bind the task to an M8
  repair record without creating a second queue item.
- Replaced the static Automations wizard with a real template catalog/editor,
  lifecycle controls, and exact-version run history view.

- create draft → publish v1 → activate v2;
- invalid provider/event/budget/timeout/approval combinations;
- stale revision rejection for concurrent edits;
- duplicate trigger returning the existing run deterministically;
- concurrency limit preventing a second active task;
- disable preventing future trigger creation;
- version history retaining each published lifecycle change.

project PostgreSQL volume was not cleared.
